# 전체 흐름 검사

```bash
npm run e2e             # 빌드부터 다시 (권장)
npm run e2e -- --fast   # 이미 빌드돼 있으면 건너뛴다
```

랜딩 → 붙여넣기 → 문장 고르기 → 미리보기 → 게시 → 내 묘비 →
쿠키를 비운 다른 방문자로 공개 묘비 방문 → 헌화 → 공유 카드까지
한 번에 밟는다. 빌드·스텁·서버·브라우저를 알아서 띄우고 끝나면 정리한다.

## 왜 있는가

로그인 뒤에만 보이는 화면 — 내 묘비, 각인 수정, 게시 — 은 오랫동안
프리뷰에 올려 손으로 눌러보는 수밖에 없었다. 구글 OAuth를 자동으로
통과할 방법이 없었기 때문이다. 그래서 "이건 프리뷰에서 확인해주세요"가
세 번 연속 반복됐다.

이 검사를 처음 돌렸을 때 바로 버그가 하나 나왔다. 그때까지 시험에 쓴
추도문은 전부 사람이 지어낸 평문이었는데, 실제 LLM은 제목·목록·인용·
강조를 섞어 내놓는다. 그대로 두면 `> "잘 살았다"` 같은 후보가 목록에
뜨고, 고르면 묘비에 꺾쇠가 새겨진다. 그래서 검사에 쓰는 추도문은
일부러 마크다운을 섞어둔다.

## 무엇을 확인하지 못하는가

여기서 통과해도 확인된 것이 **아닌** 것들이다. 스텁은 Supabase가 아니다.

| | 왜 못 하는가 | 어디서 확인하는가 |
|---|---|---|
| 진짜 구글 OAuth | 코드 교환을 통째로 건너뛴다 | 프리뷰에서 직접 로그인 |
| RLS | 스텁에 정책이 없다. **초안이 남에게 보이는지 모른다** | 스키마 적용 때 PostgreSQL로 확인 (`docs/SUPABASE-RECOVERY.md`) |
| DB 제약 · slug 트리거 | 스텁은 무엇이든 받아준다 | 위와 같음 |
| 연타 제한 (1분 10송이) | 밟지 않는다 | 실제로 눌러보기 |
| 카톡·트위터 카드 | 플랫폼이 어떻게 그리는지 | 실제 공유 |
| 모바일 키보드 · 앱 전환 | 헤드리스에 없다 | 실제 기기 |
| 계정 삭제 | 흐름에 없다 | 손으로 |

## 구성

- `stub-supabase.mjs` — GoTrue의 `/auth/v1/user`와 PostgREST의
  `tombs`·`flowers`만 흉내내는 인메모리 스텁. 세션 쿠키를 만들어준다.
- `run.mjs` — 빌드하고, 스텁과 앱과 크롬을 띄우고, 흐름을 밟고, 정리한다.

## 알아둘 것

**빌드를 건너뛰지 말 것.** `NEXT_PUBLIC_*`는 빌드 시점에 번들에 구워진다.
스텁 주소를 넣어 빌드하지 않으면 앱이 진짜 Supabase를 부르고, 검사는
엉뚱한 곳에서 실패한다. `--fast`는 직전에 이 검사가 빌드해둔 `.next`가
남아 있을 때만 쓸 것.

**이 검사는 `.next`를 스텁 주소로 덮어쓴다.** 끝난 뒤 실제 Supabase로
띄우려면 `npm run build`를 다시 해야 한다. 안 그러면 앱이 스텁을 부르고,
스텁은 이미 꺼져 있다.

크롬을 못 찾으면 `CHROME_PATH`로 알려주면 된다:

```bash
CHROME_PATH=/usr/bin/chromium npm run e2e
```

포트는 `E2E_STUB_PORT`(4996) · `E2E_APP_PORT`(3400) · `E2E_CDP_PORT`(9222)로
바꿀 수 있다.
